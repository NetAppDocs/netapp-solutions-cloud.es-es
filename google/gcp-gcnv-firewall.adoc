= Cortafuegos
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Google Cloud NetApp Volumes expone múltiples puertos TCP para servir recursos compartidos NFS y SMB:

* https://docs.cloud.google.com/netapp/volumes/docs/connect-clients/connect-nfs-clients#firewall_rules_for_nfs_volumes_access["Puertos necesarios para el acceso NFS"^]
* https://docs.cloud.google.com/netapp/volumes/docs/connect-clients/connect-smb-clients#firewall_rules_for_smb_volumes_access["Puertos necesarios para el acceso SMB"^]


Además, SMB, NFS con LDAP, incluido Kerberos, y las configuraciones de doble protocolo requieren acceso a un dominio de Windows Active Directory. Las conexiones de Active Directory deben https://docs.cloud.google.com/netapp/volumes/docs/configure-and-use/active-directory/create-ad-policy["configurado"^] para cada región. Los controladores de dominio (DC) de Active Directory se identifican mediante https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/7fcdce70-5205-44d6-9c3a-260e616a2f04["Descubrimiento de DC basado en DNS"^] utilizando los servidores DNS especificados. Se utiliza cualquiera de los DC devueltos. La lista de DC elegibles se puede limitar especificando un sitio de Active Directory.

Google Cloud NetApp Volumes se conecta mediante direcciones IP del rango CIDR asignado con el comando `gcloud compute address` mientras https://docs.cloud.google.com/netapp/volumes/docs/plan-and-prepare/networking#configure_private_services_access["Incorporación de Google Cloud NetApp Volumes"^]. Puedes utilizar este rango CIDR como direcciones de origen para configurar los cortafuegos de entrada de tus controladores de dominio de Active Directory.

Los controladores de dominio de Active Directory deben https://docs.cloud.google.com/netapp/volumes/docs/plan-and-prepare/security-considerations["Exponer puertos a los CIDR de Google Cloud NetApp Volumes como se menciona aquí"^].
